## 2. 交付级口径限制（说之前必须想清楚）

### 2.1 干净的「真实带货直播」样本 = 0 场

全库 18 个会话的音源画像核查结论：

| 会话 | 内容实质 | 可否用于统计 |
|---|---|---|
| `b217299a` | 古装剧对白 | ⚠️ 仅限「电视类连续语音」，**不可作带货样本** |
| `f941151f` | 文化讲解/纪录片 | ⚠️ 同上 |
| `d61e4b32` | **未定**（非 TTS、非影视剧） | ❌ 不得用于任何统计 |
| `5970a6d6` | 带货 TTS | ❌ 不可用于「真实直播」统计 |
| `190ba540` / `ae85dc7c` | 带货 TTS（第①级测试音） | ❌ 同上 |
| `2920b432` | **混合会话**（广告口播 + 无源间隙 + TTS） | ⛔ 只有 0~124.8s 干净区间可用 |

**因此：严禁说「已用真实带货直播验证」。** 现有实测素材是 TTS 测试音、公开转播广告口播、影视剧对白——**都不是带货直播**。

### 2.2 「流标签」不等于「内容性质」

播放源标签 `cctv13hd.m3u8` 的时隙实播为**降糖保健品广告口播**，**不是新闻**。引用流地址时不能把标签当内容依据。

### 2.3 会话引用纪律（全组生效）

引用任何会话的**统计**必须同时标注**所属时间区间**；**只写 sessionId 的引用一律视为无效引用**（`2920b432` 的 49.8s 是音源切换间隙，不是静默极值；干净窗口内最长 VAD 空隙仅 0.4s）。

## 3. 产品行为限制

1. **报告部分统计字段未统计**：ASR 连接/断线/缺口数、LLM 请求/失败数在 JSON 中为 `null`、HTML 标注「未统计」——实时事件未持久化，无法事后回算。**不要拿 `analysisRuns` 数量冒充请求数。**
   - `tests/report.test.ts` 通过只证明报告结构与口径逻辑（统计与库一致、HTML 转义、导出无密钥、脱敏），**不代表真实导出的报告里这些字段有值**。
2. **精确分析倒计时未实现**：UI 只显示最近分析状态。
3. **话术步骤阶段靠关键词触发**：漏说关键词的阶段不会出现在覆盖统计里。
4. **短会话尾部窗口可能不分析**：会话在调度边界前结束时，最后一个窗口可能未触发，最终字幕仍保存。
5. **跨片段同一语义问题不合并**：换证据仍属同一语义问题的聚合策略未实现。
6. **会话自动结束**：现已有「按排期窗口结束」路径，但无人值守的**到点自动开始未接通**；一旦开录而未结束，会持续采集、持续送 ASR、**持续计费**并造成跨场次污染（实测有会话挂 622 分钟）。
7. **~~未配置 LLM 时会重复弹 `LLM_NOT_CONFIGURED`~~（已解除，2026-10-15）**：原描述为「按 60 秒间隔一小时约 60 条，会淹没真实提示」。解除依据：`runAnalysis` 在 `llmState === "not_configured"` 时**直接跳过 LLM 分支**（`orchestrator.ts` 的 `segments.length > 0 && this.llmState !== "not_configured"` 条件），不再每个窗口都调用 `llm.analyze()`，因此不会再抛出 `LLM_NOT_CONFIGURED`；同时该窗口记 `skipped` 而非 `success`，报告不会把「没做语义分析」算成成功。**同类高频错误（`CAPTURE_QUEUE_OVERFLOW`、`PRE_START_BUFFER_OVERFLOW`、`PRE_START_BUFFER_PARTIAL`，按音频帧约 85ms 一次触发）也已改为节流：首次立即报，之后每 60 秒最多一条，累计次数经 `getErrorCount(code)` 供 UI 读取，次数不丢失。** 回归测试见 `tests/ready-gate.test.ts`「高频错误节流」「不同错误码各自独立节流」「未做语义分析不得记 success」。
8. **规则命中只是风险候选**：词法规则不能核实商品事实、不能认定违法；LLM 只输出风险提示与人工核查建议。
9. **`paceThreshold` / `silenceThresholdMs` 有 schema 无 UI 入口**。
10. **LLM 修复重试计入预算**：一次分析最多计 2 次请求；预算单位是**请求次数**，不是钱或 token。
11. **安装包未签名**（离线环境），双击会触发 SmartScreen 提示；**应用图标缺失**（使用 Electron 默认图标）。
12. **preload 中 8 个方法用字符串字面量而非 `IpcChannels` 常量**（当前值一致，未来改常量不会报错）；`capture.listDevices` 常量已定义但无 handler。
13. **DNS 瞬失败**：出现过 `getaddrinfo EAI_AGAIN asr.cloud.tencent.com`；持续断网时无法得到云端字幕。
14. **`ReportFormat` 枚举名曾为 `markdown` 但实际产出 HTML**：已改为 `["html","json"]` 并保留 `markdown` 作输入别名归一化。
15. **采集设备健康三级判据（L1 `ended` / L2 `muted` / L3 设备消失 / L4 仅电平为 0）**：设计已出，其中 L4 的旧判据（回调停更）**已废弃**并改读 `AudioContext.state`。

## 3b. 二轮（2026-10-15 上午）新增的限制与有意取舍

二轮修了 13 项（入库 12 + 证伪 1，详见 `incident-review.md` INC-16~29）。以下是**修完之后仍然存在的限制**，以及几条**必须与缺陷区分开的取舍**。

### 3b.1 时间基失真字段（不得当精确值）

`src/main/analysis/metrics.ts` 里有两种时间基混用：窗口是**墙钟**，区间是**音频轴**。漂移时：

- ⛔ **不得当精确值**：`speechMs`、`silenceMs`、`charsPerSpeechMinute`、`longestSilenceMs`
- ✅ **可当精确值**：`totalMs`、`charsPerTotalMinute`、字数、`paceChanges`、重复度

四场景实测（构造输入，非真实会话回放）：讲话在中段 → `speechMs` **0.845×（跌）**；均匀铺满 → 1.127×；全在尾部 → **归零**；窗口也随音频轴放大（纯缩放）→ 1.690×。

> **禁止写「可能偏高 1.69 倍」**：真实失真方向取决于讲话分布，可能高也可能低。
> **最危险形态**：讲话全被推出窗口 → 语速 0、最长静音 = 整个窗口。**「语速 0」「整场全是静默」这两个看起来像事实的结论，可能只是漂移的产物。**

完整契约见 `docs/metrics-timebase.md`。

### 3b.2 数字簇守卫会丢命中（有意取舍，不是缺陷）

命中区间与中文数字簇**部分相交时丢弃**（`src/main/analysis/ruleEngine.ts` 数字簇截断守卫）。代价是漏报，换来的是**不把规则没匹配的文字圈进 quote**。

- 例：规则 `\d小时` 命中「保温25小时」的「5小时」，处置是**丢弃该命中**，而不是报告 "保温二十五小时"。
- **这不是 bug**。按「宁可漏报，不可误报」的纪律，漏报只是该报的没报，误报是报一个凭空的事实。

### 3b.3 默认规则有约 20 条漏报（有意取舍，不是缺陷）

实测漏报：`七天无理由退换`、`无效退款`、`假一赔十`、`立竿见影`、`药到病除`、`零添加`、`纯天然`、`无副作用`、`孕妇可以用`、`明星同款`、`医生推荐` 等。

**有意不补正则**：补正则的代价是误报，而误报摧毁信任。后续是否补，需先有真实误报率数据。另有一条需说明：`只剩最后3件` 不命中是**纯正则写法问题**（要求「只剩」紧贴数字），**不是**归一化问题。

### 3b.4 标点打断数字-单位失配（有意取舍，不是缺陷）

「保温二十五**，**小时」「改善80**。**%」不命中。ASR 常在数字与单位间插标点，而规则 `\s*` 只容忍空白。

**有意不修**：加 `[，。、]?` 会让「改善80。%」这类 ASR 怪写法也被报成问题，属于**用误报换召回**。反例已钉住：「3.5折」正常命中（小数点是数字的一部分，不是打断）。

### 3b.5 `numeralNormalized` 的能力边界（能力限制，不是缺陷）

`RuleHit.numeralNormalized = true` 只能表示「规则看到的数字经过了中文数字折叠」——**只能识别「写法被转」，不能识别「数字被改」**。

- ASR 把「七天」识成「一天」：规则对两者都命中，quote 忠实反映被改后的原文，**`ruleEngine` 无从判断原音频是什么**。
- 想识别「数字被改」，需要**音频侧**的置信度信息，当前契约里没有。

### 3b.6 阶段判定仍是关键词竞争

`PHASE_TRIGGERS` 与 `STEP_PHASE_KEYWORDS` 二轮已统一口径（cta 排第一），但**两者仍是「命中即返回、数组顺序定胜负」**。

- 后果：同句里多个阶段词命中时，优先级高者赢，另一个不出现。
- 局限：漏说关键词的阶段不会出现在覆盖统计里（同 `3.3`）。

### 3b.7 `frameworkSource` 只有三态，不覆盖「框架被改」

`ScriptReport.frameworkSource` 三条值：`"session-bound"` / `"fallback-unrecorded"` / `"fallback-deleted"`。

- 能回答「这个报告用的是哪个框架」。
- **不能**回答「这个框架跟主播实际说的话术是不是一致」——框架被用户事后编辑过，无法从报告侧察觉。

### 3b.8 二轮全部结论来自构造输入

数字簇守卫、metrics 四场景失真方向，**全部来自构造输入**，不是真实会话回放。真实带货直播场景下的表现仍未验证（见 1.3）。

## 4. 隐私边界（不得简化为「数据不出本机」）

### 4.1 两句话必须一起说

- **本地**：会话、转写、问题、设置保存在本机 SQLite（`%APPDATA%/ai-live-monitor/live-monitor.db`）；**音频不落盘**（不保存原始音频文件）。
- **出网**：ASR **音频**（16kHz/16bit/单声道，200ms 一包）**上传腾讯云**；LLM **窗口内转写文本**上传所配置的 OpenAI 兼容服务。

> **因此「数据不出本机」是错误表述。** 正确说法是「应用与数据存储在本机；音频送 ASR、转写送 LLM」。

### 4.2 密钥

- **两条通道，环境变量优先**（2026-10-16 起）：① 设置页「密钥（加密存本机）」面板填写；② 进程环境变量 `DSH_SECRET_TENCENT_ASR_SECRET_ID` / `DSH_SECRET_TENCENT_ASR_SECRET_KEY` / `DSH_SECRET_LLM_API_KEY`。两者都提供时以环境变量为准。
- 界面填写的密钥经 Electron `safeStorage` **加密后**存本机 SQLite（`credential_store_v1`）——Windows DPAPI、macOS Keychain、Linux 系统密钥环。原文明文不落盘。
- **安全边界（重要，别把安全性说大了）**：加密解决的是「明文落在磁盘上被随手看到/被全文检索到」；它**不防**同机器同一账户下的其它程序（理论上可调用同样的系统接口解密），也不等于跨机器可用。换机器/换用户后密文无法解密，会当作未配置。
- 系统加密不可用时**拒绝落盘**（宁可不存，也不存明文）。
- 界面**不回显明文**：已配置显示 `••••••••`，环境变量已提供时显示来源并禁用输入；另有「清除本机凭证」。
- **不进日志、不进错误提示、不进导出报告**；错误文本经 `redactSecrets()` 脱敏（`secretid`/`secret_key`/`api_key`/`authorization`/`token`/`signature`/`AKID*`/`sk-*`）。
- 公开配置（APPID、base_url、model）可存设置页；`settings.get` 不回显历史敏感字段。

> **变更说明**：本条 2026-10-16 前写的是「只从环境变量读取、界面不提供密钥输入框（产物实测 `PASSWORD_INPUTS=0`）」。该描述对该日期之前的版本成立，**对当前版本已失效**——输入框已加回（见上）。旧版痕迹保留在 `docs/desktop-verification.md`、`docs/incident-review.md` 等历史记录里，属当时的真实状态，不作回溯改写。

- ⚠️ **历史遗留的明文密钥记录未被清理**（运行链路已不读取），且**不会自动迁移**到新加密通道——用户需在界面重填一次。

### 4.3 数据处理范围

- 单场预算默认 10 次 LLM 请求；超限后停止 LLM 分析（本地规则继续生效）。
- 卸载**不删除**数据库；彻底清除需手动删除 `%APPDATA%/ai-live-monitor/`。
- 演示/验收中若使用了手势旁路 `AILIVE_ACCEPTANCE_NO_GESTURE_CAPTURE=1`，**必须标注**；该旁路默认关闭，**不得出现在交付配置中**。

## 5. 环境依赖与硬约束（复现必读）

1. **本机 PowerShell 直接跑 npm 会被脚本执行策略拦截** → 用 `cmd /c "npm ..."`。
2. **启动 Electron 前必须 `$env:ELECTRON_RUN_AS_NODE = $null`**（本机默认为 `1`，会让 `require('electron')` 只返回 exe 路径）。
3. **重装依赖后必须 `npm run abi:electron`** 重建 better-sqlite3 ABI（Electron 33 要 modules 130，本机 Node 24 要 137）。
4. 跑测试用 `npm test`（electron-node、单次 run、内部清空 `DSH_SECRET_*`），**不要在测试前后切 ABI**。
5. 交付态系统声音采集**必须真实用户点击**；自动化验收若用了手势旁路必须标注。
6. macOS 若要做系统声采集，需先装 BlackHole 等虚拟声卡。
